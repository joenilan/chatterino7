## P0 — owner-requested compact chat wrapping (start here)

### What is wrong

The owner's screenshot (2026-10-15) shows an ordinary `Sery_Bot` chat announcement: a timestamp, badges, and the purple username precede a lengthy raid message with a clickable Twitch link and an emote. The first line uses the available width but each later line is **indented into a narrow body column**. The left-hand timestamp/badge gutter stays empty, unnecessarily consuming vertical space. This is **general chat-row layout**, not specifically a raid command or a Twitch system notice.

Example, schematic (without precise pixel positions):

```text
BEFORE
21:57 [badges] Sery_Bot: DreadedZombie has sent a raid
                      over to unc_xan! Join us at
                      twitch.tv/unc_xan and show love!

AFTER (desired)
21:57 [badges] Sery_Bot: DreadedZombie has sent a raid
over to unc_xan! Join us at twitch.tv/unc_xan
and show love!
```

**Requirement:** Keep timestamp/badges/username and beginning of the message inline on the first visual line; **continuation lines should start at the normal row text padding, not at the left edge of the body column**. They should consume the full usable width of the pane. This is a *soft-wrap/layout* change, not an insertion of newlines into message content. Avoid an ugly full-line separation of every username and body, and do not add an unnecessary settings toggle. Keep the same compact row padding, highlight border, and density; reduce line count where possible.

### Source-backed diagnosis (read before editing)

- `crates/desktop/src/main.rs`, chat-row construction around **lines 1416–1555** at the inspected checkpoint: an outer `.h_flex().items_start().gap_1()` holds **fixed-width timestamp**, optional **mod buttons**, **origin/source markers**, **Shared Chat avatar**, and **badges**, followed by `.flex_1().min_w_0().v_flex()` containing the actual message. Subsequent wrapped lines inherit that narrowed content column. Do not fix this by removing badges or hiding metadata.
- `crates/desktop/src/inline_chat.rs`: custom measured layout for emotes/Cheers, `LineFragment` and `line_wrapper().wrap_line(..., IndentAdjustment::NoIndent)`; the **measured child width is already reduced by its parent**, so `NoIndent` alone is insufficient. Geometry, fragment byte offsets, hit testing, emote hover and click, selection, highlighting, and drawing are interdependent.
- `crates/desktop/src/chat_text.rs`: plain-text/selection/highlight fallback. Both paths should wrap consistently.
- `crates/desktop/src/message_actions.rs`, `rich_messages.rs`, `name_paint.rs`, `replies.rs`, `chat_core::Message::copy_line()`, and any viewport/scroller/collapse-height helpers need consideration. `copy_line()` already includes the author label; avoid adding a second author or corrupting interaction ranges.

Implementation strategy to investigate: a **unified inline first-line prefix** (timestamp + action/source/badge media + author text), measured against full row width, with **prefix width reserved only on visual line 1** and unindented subsequent lines. Keep badges/controls as proper hit-testable elements even if the layout uses a custom line measurer. Share wrapping/coordinate logic between the plain-text and inline-media cases; do not solve only the plain-text case by adding manual newlines, empty spacers, negative margins, overlays, or a special-case bot renderer. Preserve one logical message and existing source offsets.
